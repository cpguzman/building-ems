# Modular Decision Architecture for Building Energy Management Systems (BiEMS)

This repository contains the Python implementation of an Energy Management System (EMS) focused on a building with Photovoltaic (PV), Battery Energy Storage System (BESS), and Electric Vehicles (EVs) with V2B capabilities.

---

## System Architecture (Data Flow)

The system is divided into three modular layers that run sequentially. The output of one layer serves as the input for the next:

### 1. Day-Ahead Optimization Module (`Optimizer_mono.py`)
* Uses mathematical optimization (MILP via Pyomo) to find the optimal economic schedule for the next 24 hours. It minimizes grid costs based on weather forecasts and dynamic tariffs.
* **Inputs:** PV forecasts (`pv.csv`), Building Base Load and Contracted Power(`pl.csv`, `pt.csv`), EV mobility profiles(`ev_inputs.csv`, `alpha.csv`), BESS inputs (`bess_inputs.csv`), Charging Points (CPs) definition (`cp_inputs.csv`), Charging Station (CSS) inputs (`css_inputs.csv`, `css_power.csv`) and Energy Tariffs (`energy_price.csv`).
* **Outputs:** Optimal planned power setpoints for the BESS (`PBess.csv`, `PBessdc.csv`) and the EVs (`PEV.csv`, `PEVdc.csv`).

### 2. Strategy Translation Module (`Translator_mono.py`)
* Acts as a semantic translator. It reads the continuous mathematical setpoints generated by the optimizer and classifies each hour into one of several strategic **Operational Modes** (*Arbitrage*, *Peak Shaving*, *Self-Consumption*).
* **Inputs:** CSV files generated by Layer 1 including grid import and export power, EV charging/discharging power setpoints and BESS charging/discharging power setpoints (`grid_import.csv`, `grid_export.csv`, `PEV_h.csv`, `PEVdc_h.csv`, `PBess_h.csv`, `PBessdc_h.csv`), that are inside the `RESULTS_*` folder, and the contracted power limit (`css_power.csv`).
* **Outputs:** `Modos_Operacao_Analisados.csv` file inside the corresponding `RESULTS_*` folder, which acts as the "strategic intent" for the real-time controller.

### 3. Real-Time Control Module (`RealTime_mono.py`)
* Operates using a rule-based logic, reading the Operational Modes which converts in power setpoints and, at each instant, measures the actual building load. 
* **Inputs:** Modes file from Layer 2 (`Modos_Operacao_Analisados.csv`) - the code asks in which `RESULTS_*` folder it is located, simulated real measurements of the building, PV production, EVs inputs, BESS inputs and CSS/ CP inputs and the Energy Tariffs (`pl.csv`, `pt.csv`, `pv.csv`, `evs_inputs`, `alpha.csv`, `bess_inputs`, `css_power.csv`, `cp_inputs.csv`, `energy_price.csv` ), all located in the `Measurements` folder.
* **Outputs:** `Resultados_RTO_Final.csv` file containing all the results togheter and automatically generated charts for global power balance and EV status.

## Directory Structure

For the system to function correctly, files must be organized as follows:

```text
├── Measurements/               # Input data folder used by the RealTime_mono.py file
│   ├── pv.csv                  # Solar generation
│   ├── pl.csv                  # Building base load
│   ├── energy_price.csv        # Dynamic import/export tariffs
│   ├── alpha.csv               # Actual physical availability of EVs at the plug
│   ├── evs_inputs.csv          # EV battery characteristics
│   └── cp_inputs.csv           # Charging point characteristics (Continuous vs Binary)
├── RESULTS_*/                  # Folder generated by the Optimizer
│   ├── PBess.csv               
│   ├── PEV.csv                 
│   └── Modos_Operacao_Analisados.csv  # Generated by the Translator
├── pv.csv                      # Input data used by the Optimizer_mono.py file
├── pt.csv
├── ev_inputs.csv
├── alpha.csv
├── bess_inputs.csv
├── cp_inputs.csv
├── css_inputs.csv
├── css_power.csv
├── energy_price.csv
├── Optimizer_mono.py           # Layer 1 Script
├── Translator_mono.py          # Layer 2 Script
└── RealTime_mono.py            # Layer 3 Script
